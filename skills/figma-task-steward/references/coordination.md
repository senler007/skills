# 账本协议

同一规范化工作区对应个人 Codex 目录中一份账本：$CODEX_HOME/figma-task-steward/<路径哈希>/state.json（默认 ~/.codex）。不同路径不自动视为同一工作区；执行会话使用真实项目 local 路径。此协议不能隔离人工、未登记会话或跨机器写入。

## 原子读写

从任意工作目录运行：

```powershell
python '<skill目录>/scripts/ledger.py' --workspace '<项目绝对路径>' show
python '<skill目录>/scripts/ledger.py' --workspace '<项目绝对路径>' commit --expected 0 --file '<候选JSON绝对路径>'
```

show 返回 path 和 state。候选 JSON 是完整 state，不带外层包装，保留刚读取的 revision 和所有不相关字段；候选文件放在项目外临时目录。commit 在进程锁内重读、比较版本并原子替换，成功自动递增 revision。以实际返回版本为准，不能猜测“上次 +1”，其他执行者也可能提交。

版本冲突退出码 2：重读并重新判断，不盲目重试旧快照。锁忙或损坏文件退出码 1：不能据此清除持有者。自动审批或权限拒绝不是 CAS 冲突；不得换工具、换会话或直接写 state.json 绕过拒绝。

初始结构：

```json
{
  "revision": 0,
  "surveyed": false,
  "manager": null,
  "workspace": {"owner_task": null, "borrower_task": null},
  "tasks": {}
}
```

manager 为 {"thread_id":"真实ID","heartbeat_id":null}。surveyed 仅在实际排查既有使用者且归属明确后设 true；发现未登记写入者须重新核对。不得添加 workspace 内的任意字段，脚本只接受 owner_task 和 borrower_task；额外信息存入任务或顶层字段。

任务键 fileKey:nodeId：

```json
{
  "title": "任务标题",
  "node_url": "已核实的节点链接",
  "dispatch_token": "唯一UUID",
  "thread_id": null,
  "status": "dispatching",
  "report": null
}
```

thread_id 必须真实且各规范任务绑定唯一；状态为 dispatching/pending/clarifying/awaiting_plan/ready/running/blocked/done/cancelled。按需记录：
- approval：用户原话、来源 thread_id、可取得的 turn_id、对应具体方案及覆盖范围。
- clarification_progress：最新需求快照来源、dispatch_sent/active/question_asked/needs_project_facts/awaiting_plan、实际问题与未覆盖清单。启动中不伪装成已提问。
- workspace_access_scope/read_only_claim：只读目的、允许操作、取得权限来源。
- completed_iterations/reassignment_release：已完成独立范围、验证、剩余问题、安全状态与释放原因。
- pending_question/blocked_reason：当前实际缺口及首次通知，旧问题被新答案解决时更新。
- scheduling_hold：暂停对象、范围、原因与后续明确授权的局部例外，不把它当作永久全局开关。
- communication_policy：顶层保存当前消息规则；在正常恢复和操作批次前读取，不通过广播唤醒会话。排队请求与最新更正保存到各任务，待实际授权时合并发送。

任务终态和旧成果保留防止重派。重新执行须有新范围，不能覆盖历史完成事实。脚本仅验证结构与唯一占用，授权、暂停和安全事实由代理核实。

## 会话创建与边界修正

正常先 CAS 预留唯一令牌，再创建、绑定、启动。创建失败保留失败结果；返回结果不明先按令牌查找，不能再次创建。

用户明确要求新建，而预登记暂不可用时，若创建操作本身仍被允许，可以先创建一次只处理已提供资料的澄清会话；持久保存返回真实 ID、令牌/来源标记和 pending_binding 原因。保存到允许写入的项目外恢复记录（如本自动化 memory.md），由当前或接班管家在下次事件核对恢复；若拒绝也覆盖该写入，只保留工具真实创建结果与会话记录，不能换文件规避拒绝。它不具备共享项目权限，不能派它补做被拒绝的操作。恢复时绑定这个已有会话。分别报告创建、绑定、授予权限的实际结果。

task_node_aliases 只用于同一任务移动、重命名或同范围新卡。分别摆放的不同需求不能因共用代码映射成一个任务。用户要求拆分旧合并任务时：
1. 为拆出卡建立独立键/令牌并创建或核实指定会话。
2. CAS 绑定其真实 ID，移除错误 alias；保留旧任务成果与迁移记录。
3. 将与该范围相关的用户答案、历史限制、未决项交接过去；账本取消原会话对该范围的后续派发。原会话正在处理这个范围时，管家发送一次边界更正；原会话已结束或排队时保存到下一次恢复，不为通知停止而唤醒。旧实施批准仅在仍覆盖同一具体范围时有效。
4. 不重复采访，不把已完成子范围或其他任务一并重开。

用户明确合并讨论时，用 canonical_discussion_task 等额外字段指向接收任务，并抑制旧任务独立派发；保留旧 thread_id 和未完成历史，不把两个规范任务绑定同一个 thread_id。

## 空闲只读：直接领取

已绑定执行会话可自行登记短暂只读 owner，无需请求—批准—确认消息链，但必须同时满足：
1. 真实 thread_id 与派发令牌匹配，任务未终结，本轮确有项目事实需要查明。
2. surveyed 为 true，owner_task 与 borrower_task 均为空，没有已知人工操作或未登记写入冲突。
3. 用户授权/当前暂停允许本次调查；没有已排定、应优先进入的就绪实施任务或其他授权范围冲突。
4. 使用最新 revision CAS 设置 owner_task 为自身任务键，记录 read_only_claim 和具体范围，状态保持 clarifying/awaiting_plan。成功后核实返回状态再查；冲突则重新判断。

管家也可在绑定时一次性授予只读，避免多次唤醒。空闲直接领取只解决只读调查，不允许执行者自行领取实施或修改其他任务授权。

只读包含源码、文档、现有元数据等无副作用调查；禁止写项目、编译、切换 Git、生成缓存/索引、启动或控制 UE/PIE。不得以“查询工具”名义触发编辑器写入。查完立即 CAS 记录结论并释放 owner，再给当前管家一次必要回报，不等用户回答或归还确认。

## 实施、实际占用与释放

- 只有当前管家给已批准且依赖满足的 AI 任务授予实施 owner，并将 ready 转 running。若该任务已持有只读 owner，先结束调查到安全点；管家可 CAS 明确改授实施范围，或执行者先释放再由管家授予。执行者不能仅凭用户批准自行改权限。任务恢复前核实批准范围和项目变化。
- 另一任务占用时，申请者向当前管家登记一次请求后结束本轮。管家默认排到实际释放后，不逐条转发、不要求持有者为每个请求暂停。确有当前依赖需要短暂借阅时，管家合并请求，向持有者发一次安全点交接请求；等待真实安全回报，不推定已停。
- 持有者到安全点确认后台停止，记录暂停范围并只向管家回报。管家核实当前 owner、暂停证据和 borrower 为空后 CAS 登记一个 borrower，owner 保持不变，再给借阅者一次实际授权。借阅者已绑定且为 clarifying/awaiting_plan；有 borrower 时 owner 停止项目操作。
- 借阅者查完只清空 borrower，向当前管家回报一次；管家核实归还后给 owner 一次恢复消息，owner 重读账本才恢复。执行者之间不发申请、授予、暂停或恢复消息。申请、预计交接及过期消息都不是许可。
- 持有者无可继续的已授权工作时，确认项目操作及后台写入停止、无 borrower，CAS 保存 reassignment_release 并清空 owner，保留未完成状态。通知管家改派；不能仅凭 turn 结束、空闲时长或等待回复强制释放。
- 全部范围与必要验证完成：执行者同次 CAS 写 done、report 并清空 owner。未决事项、未完成验证或新范围尚未做时，只记录子范围成果，不能整体 done。
- 人工原有 UE/PIE 会话不是可随便清理的测试残留；调查前记录基线，结束恢复自己改动的状态，不能为造出“PIE=[]”关闭用户会话。资源或后台归属不清先协调。

## 管家与消息交接

调度消息只能由账本中的当前管家发送给实际需要行动的执行者。等待者无权时保持安静；它收到重复等待通知或其他执行者的调度消息时，不操作项目、不回消息形成循环、不再向用户播报暂停。若消息暴露真实归属冲突，记录证据并向当前管家报告一次。

管家发送授权前核实成功提交返回的实际状态、任务、权限和范围。条件分支未执行、CAS 冲突或提交失败时不发送预先写好的成功消息。一次有效授权携带累积更正；排队状态、普通进度、例行验收和规则变更只入账，不为此唤醒已结束会话。已发送的同一授权不重复发；仅确认未送达的暂时失败可重试一次。

旧管家完成在途派发事务后 CAS 改 manager.thread_id，其他任务与占用不变，再消息通知新管家。禁止日期/超时抢占；迟到回报转发当前管家，不继续旧调度。

任务安全释放或全部完成后，先记录状态，再重读 manager.thread_id，通过 send_message_to_thread 主动回报。可保存 completion_notification 的目标、发送结果和错误；管家按任务键与阶段去重。相同状态不重复发送，普通答案无需每次回报，影响共享依赖或授权的变化再报；接收方不发送纯确认形成循环。

消息失败保留成果供下次事件恢复，不能重复实施，也不能依赖 heartbeat 发现完成。仅在已确认未发送的暂时错误下重试一次。
